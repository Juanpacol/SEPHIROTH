# 2026-09-25 (session 17)

## Session — Radiology abstention bug root-caused; observation-grounded verification shipped (SPEC-004 1.2.0, ADR-018)

**Goal**

Fix a real, reproduced bug: after a successful image analysis, asking the
copilot about it returned "There isn't enough verified evidence to answer
this confidently" instead of the actual finding — even though
`describe_medical_image` had returned a genuine, correct description.

**Root cause**

`src/sephiroth/verification/evidence.py`'s `_EVIDENCE_LIST_KEYS` allowlist
deliberately excludes a vision/imaging tool's own output (`description`,
`findings`) from `harvest_evidence`, to prevent an answer from verifying
itself. Correct in isolation, but the only production effect was that
RadiologyAgent consultations always harvested zero evidence — every claim
became `UNKNOWN`, confidence hit `0.0`, and `abstention.decide` fired
`INSUFFICIENT_EVIDENCE`, discarding a correct answer. `DrugSafetyAgent`
never hit this because `check_drug_interactions`'s `interactions` key was
already in the allowlist.

**Fix (SPEC-004 1.2.0, ADR-018)**

Separated *faithfulness to a tool's own output* (checkable, same idea as
`citation_guard`) from *corroboration by independent evidence* (what the
exclusion correctly protects). Added:

- `harvest_observations` (`verification/evidence.py`) — builds
  `EvidenceRecord(source_type=TOOL_OUTPUT)` from a perception tool's
  successful output, kept separate from `harvest_evidence`.
- `VerificationStatus.OBSERVED` — assigned deterministically (never by the
  LLM judge) when a claim's cited evidence is entirely tool-output.
- `grounded_claim_ratio`/`OBSERVED_WEIGHT` (`contracts/claims.py`, not
  `verification/`, to keep `contracts` a leaf package —
  `verification/confidence.py` imports and re-exports the constant).
- `OBSERVED_BANNER` (`safety/abstention.py`) — a distinct partial banner
  from the generic one.
- The executor now overwrites each claim's `originating_agent` with the
  real answering agent id, fixing a related bug where claims were tagged
  `"evidence"` regardless of which agent actually answered.

An invented (tool-unreported) high-risk finding still abstains unchanged —
this was a design gap, not a safety-gate weakening.

**Process**

Followed SDD fully: discovered mid-flight that the correct move was
amending `SPEC-004` (1.1.0 → 1.2.0) rather than authoring a new spec —
precedent (`SPEC-005`/`SPEC-006`'s own prior amendments) shows additive
contract changes stay on the owning spec, same phase. Three branches/PRs:
`SF065` (spec + `ADR-018`, Draft), `SF066` (tests-first, all
`xfail(strict=False)`, Approved), `SF067` (implementation, Implemented).

**Incident during SF067**

A bulk regex script meant to strip the temporary `xfail` scaffolding
markers matched too greedily and silently deleted 8 whole test functions
across the SF066 files — including the two most important ones (the basic
OBSERVED-promotion tests and the main end-to-end radiology integration
test). Caught by diffing the working tree against the SF066 commit
(`git diff 903bd3b -- <files>`) and comparing `def test_` counts per file
before trusting the suite was complete. All 8 restored by hand. Lesson: a
bulk find-and-replace across multiple test files needs a diff-based
sanity check against the last known-good commit before being trusted,
not just "tests still pass" — a deleted test also "passes."
