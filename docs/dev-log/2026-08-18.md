# 2026-08-18

## Session 1 — Phase 2: Tool Runtime

**Goal**

Implement `SPEC-002`: relocate the MCP dispatcher to `sephiroth.tools`, add a
per-call timeout and capability tags, close DEBT-004 (unauthenticated direct
tool endpoints).

**Did**

- Wrote `tests/test_tool_runtime.py` and `tests/test_mcp_shims.py` first,
  confirmed they failed against nonexistent code.
- Built `src/sephiroth/tools/{__init__,runtime,servers}.py` — `ToolRuntime` is
  `MCPRegistry` relocated and renamed, with a timeout added to `execute()` and
  a new `tags_for()`.
- Added `Depends(get_current_user)` to all 8 endpoints across
  `medical.py`/`rag.py`; updated the tests that assumed no auth.
- Shimmed `intelligence/mcp/registry.py`.

**Decisions**

- **No generic retry or circuit breaker** (SPEC-002 NG-1/NG-2). The two
  I/O-performing tools already retry inside their own logic; a second layer
  would double-retry the same failure for no measured benefit, and no
  incident justifies a circuit breaker yet.
- **Auth added directly, no permissive rollout.** Unlike Phase 0's tool
  whitelist (where something could plausibly depend on the hole), nothing
  legitimately depends on these endpoints being public — every comparable
  endpoint already requires auth.

**Tried and rejected**

- Nothing — followed the approved plan directly. The complications below were
  bugs to fix, not design choices to revisit.

**Problems**

- **Found before Phase 2 even started: the Phase 1 commit was broken.**
  Branching from `main` instead of `phase-1-model-provider` by mistake
  surfaced a `.gitignore` rule (`models/`, meant for model-weight downloads)
  that had silently excluded all of `src/sephiroth/models/` from the Phase 1
  commit — `git add -A` skipped seven files, and the pushed commit contained
  only shim code that imports from a module that was never committed. Every
  verification that session (tests, coverage, eval, two Docker smoke tests)
  passed anyway, because git leaves ignored/untracked files on disk across
  branch switches — none of that testing had ever touched what was actually
  *committed*. Fixed by anchoring the rule to the repo root and adding the
  missing files as a new commit, this time verified from a `git worktree`
  detached at the fixed commit — not the working directory. Full account in
  the previous day's log, Session 2.
- **A genuine circular import**, caught immediately by the new tests:
  `sephiroth.tools.servers` imports the five FastMCP server objects back from
  `intelligence.mcp`, and the `intelligence/mcp/registry.py` shim imports
  `sephiroth.tools` — each package needed the other fully initialized at the
  same time, regardless of which one a caller imported first. Fixed by making
  `intelligence/mcp/__init__.py` resolve `MCPRegistry`/`get_registry` lazily
  via `__getattr__` (PEP 562) instead of importing them eagerly, so importing
  the package no longer forces the shim's import chain to run. The shim
  module itself stayed a pure re-export.
- One test assertion of my own was wrong (expected `get_tool_runtime.__module__
  == "sephiroth.tools"`; it's actually `"sephiroth.tools.runtime"`, where the
  function is truly defined) — caught immediately by running it, one-line fix.

**A scope decision, flagged rather than silently made**

The migration charter's original shim schedule had `intelligence/llm/*`
(created Phase 1) deleted in Phase 2. This phase's *approved* plan scoped only
the Tool Runtime and didn't include that cleanup — deleting the LLM shims now
would mean rewriting imports across roughly 16 unrelated files, outside what
was approved. Deferred to Phase 3 and tracked as `DEBT-008`, with an explicit
note that it must not slip further (the charter's own rule: a shim surviving
two phases becomes permanent).
