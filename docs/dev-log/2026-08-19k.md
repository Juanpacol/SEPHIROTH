# 2026-08-19 (session 11)

## Session — Phase A: close the unauthenticated-PHI-exposure hole

**Goal**

First of 5 phases in a new plan (landing page, brand icon, patient
portal, scheduling). Phase A is independent of the rest and ships first:
`GET/POST /api/patients`, `GET /api/patients/{id}`,
`GET /api/patients/{id}/timeline`, and `GET /api/dashboard/stats` had
**no auth at all** — any unauthenticated caller could list every
patient's PHI or read aggregate risk counts. Discovered during planning
for the patient-portal work (which makes this worse: a patient login
without this fix would mean any logged-in patient could read every other
patient's chart), but real and worth fixing on its own regardless of the
portal.

**Did**

- `platform/api/main.py`: added a shared
  `_authenticated = [Depends(get_current_user)]` and attached it via
  `dependencies=` to the `agents`, `patients`, `medical`, `rag`, and
  `dashboard` router includes. Router-level, not handler-level — a new
  route added to any of these files is protected the moment it exists,
  closing the class of bug rather than patching today's instances.
  `get_current_user` is a deliberate stand-in for a future
  `require_clinician` (Phase B of the same plan); swapping it in later is
  a one-line change once roles exist.
- `tests/test_api_patients_rag.py` builds its own `FastAPI()` app rather
  than importing `api.main`'s, so it needed the same `dependencies=`
  mirrored onto its `patients`/`dashboard` includes, or the fix would be
  invisible to this test file. Updated every existing test that hit those
  two routers unauthenticated to register a clinician and pass a Bearer
  header instead.
- Added 6 regression-lock tests, written to fail against `main` first and
  confirmed they did: `test_unauthenticated_cannot_{list,create}_patient`,
  `_get_patient_detail`, `_get_patient_timeline`, and
  `_read_dashboard_stats` — all assert 401 with no header.
- `scripts/smoke_test.sh`: its dashboard check called
  `GET /api/dashboard/stats` **without** the token it already has from
  registering — added the header. Grepped `scripts/`, `README.md`,
  `docs/`, `examples/` for other unauthenticated calls to these routes;
  found none.

**Decisions**

- **Router-level `dependencies=`, not a per-handler audit.** The bug
  existed because auth was opt-in per handler; the fix has to change that
  shape, not just add the two missing `Depends()` calls, or the same
  class of bug reappears the next time someone adds a route to
  `patients.py`/`dashboard.py` and forgets.
- **`get_current_user` as a temporary stand-in for `require_clinician`.**
  Building the role-aware dependency now, before Phase B's model/migration
  exist, would mean either a fake role check or blocking this fix on a
  much larger change. The real fix here is the *enforcement point*
  (router-level), not the *identity* of the guard — swapping in role
  checking later is one import change in `main.py`.

**Tried and rejected**

- Nothing — this was a narrowly-scoped, well-understood fix with no
  design ambiguity once the missing-auth routes were confirmed by grep.
