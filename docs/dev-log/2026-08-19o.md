# 2026-08-19 (session 15)

## Session — Phase E: landing page, brand icon, entry flow (final phase)

**Goal**

Fifth and final phase of the landing/icon/portal/scheduling plan. An
English landing page at `/` with interactive explanations of how
SEPHIROTH works, an original brand icon, and the logged-out-lands-on-
landing / logged-in-skips-straight-to-dashboard entry flow.

**Did**

- `app/(marketing)/` route group: landing page with its own nav/footer,
  escaping `AppShell`'s chrome via the `isChromelessRoute()` predicate
  already built in Phase D (just added `/` to its list).
- 4 interactive demos, all zero-dependency, reusing existing design
  tokens: a 5-stage consultation stepper (routing → specialists →
  synthesize → citation guard → verify), a claim-hover panel showing the
  5 verification states, a raw-vs-guarded citation toggle (same
  segmented-control markup as the existing `ThemeToggle`), and a
  confidence slider that flips the output to a decline below threshold.
  Autoplay is off by default and pauses on hover/focus; transitions
  respect `prefers-reduced-motion`.
- Original brand mark: a single-wing signature, not a drawing of any
  character — built from stated arithmetic construction rules (one
  quadratic-arc spine, feather ribs as short secondary arcs, explicit
  coordinates documented in the component itself) so the geometry is
  provably original, not traced from anything. Two forms: a full 4-rib
  `WingMark` component for on-page use, a simplified 2-rib form baked
  into `app/icon.svg` for favicon sizes where the extra ribs would mush
  together.
- `app/apple-icon.tsx`/`app/opengraph-image.tsx` via Next's built-in
  `next/og` — deliberately no custom font (a font fetch inside
  `ImageResponse` has no network guarantee in CI; used the system stack).
- Entry flow: an inline `<head>` script mirroring the existing,
  already-proven `THEME_INIT_SCRIPT` pattern — checks `localStorage` for
  a token and role, redirects before first paint, paired with one CSS
  rule to hide the body during the redirect. A client-side fallback
  component covers soft navigation back to `/`.
- Swapped the old gradient-square "S" brand mark for `WingMark` in the
  three places it appeared (`sidebar.tsx`, `login/page.tsx`,
  `portal/claim/page.tsx`).

**Decisions**

- **The `sephiroth` gradient never appears on the landing page's chrome**
  — only inside the interactive demos' mock AI-output cards (the
  Coordinator draft, the abstention-gate answer), the same rule the rest
  of the app already follows. Wrote this as a comment at the top of the
  landing page file itself so a future edit doesn't casually "brighten
  it up."
- **One consolidated page file instead of 8 separate section files** —
  the plan sketched per-section files; given the actual section count
  and content size, one well-commented file was more honest than
  splitting for its own sake. No section is complex enough on its own to
  earn a separate file yet.
- **No custom font in the OG/apple-icon images.** A tempting way to match
  the Manrope brand font exactly, but `next/og`'s `ImageResponse` would
  need to fetch it at build/request time — a real hang risk in CI with no
  network guarantee. System font stack instead; the images have almost
  no text anyway (mostly the wing mark).

**Tried and rejected**

- Nothing structural — the plan's mechanism choices (inline script over
  middleware, `next/og` over external image generation, hand-authored
  SVG over an icon library) all held up unchanged during implementation.

**Problems**

- **No browser automation tool was available in this environment**,
  same as Phase D. This phase's core mechanism — the pre-paint redirect
  eliminating a landing-page flash for logged-in visitors — is
  specifically the kind of thing that's hard to confirm without watching
  it happen in a real browser. Compensated with: a clean `npm run build`
  (regression guard: `/` still shows as `○ Static`, proving the page
  didn't accidentally become dynamic), and curling a production
  (`next start`) server for every new route including `/icon.svg`,
  `/apple-icon`, `/opengraph-image`, confirming the landing page's actual
  rendered HTML contains the hero copy and the wing-mark SVG — real
  content, not an empty shell. The flash-elimination claim itself rests
  on this being the exact same pattern as the already-working
  `THEME_INIT_SCRIPT`, not on having watched it not-flash.

**Results**

- `npm run build`: clean, all 18 routes (2 dynamic app routes, 2 edge
  image routes) compile and type-check.
- Production server curled: `/`, `/icon.svg`, `/apple-icon`,
  `/opengraph-image`, `/login`, `/portal/claim` all 200; landing page
  HTML contains the hero heading text and an inline SVG confirming the
  wing mark actually renders server-side.
