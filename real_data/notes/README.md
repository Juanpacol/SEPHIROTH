# Clinical notes — 100% synthetic

**Source of the underlying facts:** the real patients in `real_data/patients/sample_patients.json` (parsed from Synthea's public Coherent Data Set — see `../patients/README.md`).

## How `sample_notes.json` was actually produced

`generate_notes.py` is designed to turn each parsed Synthea patient's conditions/medications/timeline into a natural-language progress note via SEPHIROTH's own Gemini client (`intelligence.llm.get_llm_client()`) — the same role `synthetichealth/chatty-notes` (Apache 2.0) plays for Synthea's FHIR bundles.

**Honest note on the currently-committed file:** the 6 notes in `sample_notes.json` were written by hand, not generated by the script — this project's Gemini free-tier daily quota was exhausted (see README § Evaluation → "Free-tier quota management") when this file was built. Every clinical fact in each note (conditions, medications, recent events) is taken directly from the corresponding patient's real, parsed Synthea data — nothing is invented — but the prose itself is manually authored, not LLM-generated.

**To regenerate with real LLM-authored notes** once quota is available:

```bash
PYTHONPATH=.:platform python3 real_data/notes/generate_notes.py
```

This overwrites `sample_notes.json` with Gemini-generated notes over the same patients — at that point the notes become genuinely LLM-authored (the underlying facts don't change, since they come from the same structured data either way).

## Usage

`sample_notes.json` is a small, committed list of `{patient_id, note_date, content}` — used by `examples/real_data_example.py` to exercise `intelligence/nlp/timeline_extractor.py::extract_events` against realistic clinical prose instead of hand-typed test strings.
